# 独立レビュー — v2.9.0 source preview

## ソースと実データ

別の読み取り専用レビューで、次を確認しました。

- 8個の圧縮分割メッシュの個別／結合SHA-256、展開後106,398,904バイトの完全一致
- GLBの1,059メッシュすべてについて、ネイティブデータと位置・面順・UV・Color32を比較。glTFのV反転と材質UVスケールを考慮し、一致
- 凍結したv2.8の実バイナリから保護データを独立に照合。東西分割した8メッシュも再構成し、頂点共有・属性・面順が完全一致
- 床・透明壁の衝突バイナリSHA-256は `51e395fbea8f6d29ffbebe76bb484f465c671508f93bf75afa9294ccff630ddb` のまま
- 49席、12階層移動、77個の固体BoxCollider、6通路のメタデータはv2.8と同一
- 店舗の実メッシュと物理形状の指定経路190領域を独立に再検査し、失敗0。階段入口の局所的な許容接触15件は前版と同じ
- 変更された瓦・木部・金物32バッチのうち、床上2.60mより低い面は位置・UV・色・向きを含めて同一
- 書き出し後の瓦・料理・銅樋は、形状と法線マップ用UVの退化なし
- 現行データの敵対的な変更を含む1,912検査、頂点色3検査、屋根16条件、料理16条件と不正変更8条件、品書き8枚の向きを確認

## 画像と既存の制限

ラーメン、修正したS03の品書き、斜めからの軒先の制作プレビューを確認。入力GLBのSHA-256は `21062ddd9b829c976db5dd0b9429c88ff7a412b5cd1d5994d1c386c989875907` です。

最終の1280×800・64サンプル画像2枚も目視確認しました。軒先の瓦口・銅樋・看板と動線、料理の器・卵・麺・肉・葱に新たな目立つ貫通や陰影破綻は見つかりませんでした。保存した未処理PNGのSHA-256、メタデータ、納品コピーの一致も独立に確認しています。

GitのCRLF有効設定で9個の圧縮資産を一時リポジトリへ追加・チェックアウトし、バイト列の完全一致を独立再現。料理の再生成画像3枚と今回の実際の同梱PNGの一致も確認しています。

既存のCrownLookoutBridge/Band19のGLBには、参照される2頂点のゼロ法線が残っています。この保護メッシュはv2.8と完全に同じで、今回の改修による退行ではありません。Unity側は法線を再計算しますが、実行していないため、それで表示が解決するとは保証していません。Unityでの樹冠橋の表示確認項目です。
