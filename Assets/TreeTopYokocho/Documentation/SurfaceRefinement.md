# 瓦・排水・器の表面仕上げ — v2.9.0

## 歩いて近づいたときに見える造作

瓦の軒先を閉じた丸い飾りから、中空の口と厚みを持つ形へ変更しました。屋根の段重ね、棟の半円形の端、控えめな焼き色差を実形状と頂点色で表現しています。手続き生成のKawara用既存PBR画像は維持しました。

雨樋には開いた半円断面、薄い端板、巻き縁、受け金具と既存の縦樋へ続く継手があります。垂木先端との干渉を見直し、樋を滴下縁へ寄せました。変更した造作は床上2.60mより上に収め、店員入口や客席付近の低い縦樋は維持しています。

ラーメンの器を薄い縁と高台にし、半切りの卵、曲がった海苔、細い麺、控えめな肉の繊維・脂、細かな葱を更新。焼き鳥の艶を一様なプラスチック状から部分的な焼き色・表面の粗さへ調整しました。器の釉薬も反復する青い模様を抑えています。同じ3枚の1024×512画像を使用し、素材数は増やしていません。

奥の品書きは、正面から文字が鏡像になるUVと重なった裏面を修正。書き出し後の8枚すべてについて面の向きと文字の上下左右を検査します。

## 描画の分割と容量

隣の巨木の葉3材質・小枝1材質を東西に分割し、左右両方にまたがる巨大な描画範囲を小さくしました。116,618三角形の位置・UV・頂点色・面の向き・共有頂点は凍結したv2.8データと一致することを検査します。描画バッチは4個増えます。UnityでカリングやFPSが改善したという実測ではありません。

- 全体: 2,630,961 → 2,587,709三角形（43,252減）
- 描画ソースバッチ: 1,047 → 1,059（東西分割4、8店舗の銅樋8）
- 編集メッシュ: 108,526,873 → 106,398,904バイト
- 編集用gzip: 32,452,512 → 32,511,601バイト。形状は減りましたが圧縮後は59,089バイト増えています
- 食器・料理の3画像: 1,663,909 → 1,537,542バイト。新しい画像や画像解像度の追加なし

これらは制作資産の値です。約50MBを目標とするWindows版VRChatワールドの圧縮ビルド容量、VRAM、FPS、ドローコールは未測定です。

## 検査と再現

`python Source/run_checks.py` は実メッシュの床・壁・指定動線に加え、店舗入口、客席、枝、看板UV、頂点色、保護された遠景の厳密な比較を行います。比較用の期待値は `Docs/baselines` に固定し、再生成によって自動更新しません。

雨樋・瓦の低い領域と旧版との比較、料理の配置範囲・RNG・未変更の画像タイルは個別の制作検査でも確認しています。最終結果と独立レビューの対象はリリース記録を参照してください。

Blenderプレビューは実際の今回のGLBと画像から再描画しています。Unity/VRChat実行画面ではありません。C#・Udon・Shaderコンパイル、ライトベイク、Unity物理、実機・複数人テストは次のUnity検証段階に残ります。
