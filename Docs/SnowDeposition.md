# 雪山の露岩と積雪

v2.12では、北の山脈が均一な白い帽子に見えていた箇所を調整しました。既存の山の形を変えず、斜面に沿って露岩からつながる雪の薄い部分を頂点色で表現しています。

## 変更の境界

- 4セクターのAlpineSnow / AlpineSnowShade、合計8バッチのRGBのみ変更
- 頂点位置・UV・三角形の順序・alpha・マテリアル定義は完全に維持
- 追加の形状、画像、マテリアル、描画バッチ、ライトは0
- 他の1,043個の既存ネイティブバッチは維持。舞台屋根の4追加バッチは別の変更として検査
- 山脈の12バッチ、7,461頂点、11,500三角形という元の構成は不変

色は雪の被覆量であり、固定の光源や影を塗り込んだものではありません。暗い領域は、すべての異なる被覆値のしきい値で、元の岩との境界に地形上つながるよう構成しました。露岩の色は既存岩面の平均的な線形反射色に合わせています。

元の滑らかな雪線の切断形状は保持しています。過去の高周波な雪線では、背後の岩が手前の雪の上に浮く小片に見える問題があったためです。地形上の連続性は、あらゆる視点で小さな投影片が現れないことを保証しません。広い比較画像には数ピクセルのしきい値依存領域が残る場合があります。

## 検査と再現

`python Source/test_snow_deposition.py --report Docs/snow_deposition_validation.json`

7項目で元の山生成関数、固定した旧データ、承認済みの8色ハッシュ、位置・UV・面順・alpha、乱数状態、処理の有無、再生成、被覆領域の接続を検査します。既存の固定資料を更新せず、featureが厳密なJSONのtrueであるときだけ新しい色を認めます。

ネイティブ制作データ単独の同条件gzip比較では約4.4KBの増加です。舞台屋根と統合した実測はリリースノートを参照してください。Windowsワールドの圧縮ビルド容量は未測定です。

比較・完成プレビューは実際のメッシュをBlenderで描画しています。Unityの頂点色シェーダー、遠景のちらつき、VR両眼での見え方は実機検査が必要です。元の粗い三角形分割は変えていません。
