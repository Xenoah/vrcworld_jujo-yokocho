# 能舞台風の屋根：追加造形

既存の四方に開いた舞台を保ち、瓦の重なり、厚さのある軒先、控えめな棟・隅棟、梁の木栓と端部、妻側の垂木を加える視覚専用の追加です。参考画像の瓦・木造表現を取り入れていますが、歴史建築の厳密な復元を主張するものではありません。

## 造形

- 348枚の薄い瓦シェル。厚さ8 mm、横ピッチ380 mm。浅い受け面と丸い山を9点の曲線断面で形成
- 長手側は9段、妻側は6段。流れ方向の段間隔は約343 mm／312 mm、重なり45 mm
- 瓦の溝は流れ方向に整列。切り詰めた角部を隅棟で覆う構成
- 棟9区間、隅棟32区間。既存の丸い棟材はそのまま内部に残す
- 梁の接合部8か所、木栓16本、妻側の垂木12本
- 既存のKawara、StageCypress、DarkTimberを共有。新規マテリアル・画像は0

## 保護範囲と例外

既存の舞台12バッチと照明3バッチは、頂点・三角形・UV・Color32を含めて変更しません。床、柱の当たり判定、通行幅、目線の高さの開放性、既存の位置メタデータは維持します。

追加部分の舞台ローカル座標の範囲はX ±2.965645 m、Y ±2.889785 m、Z 2.7573947〜4.271 mです。水平方向は既存屋根の範囲内。頂部だけ既存の4.265 mから6 mm上がります。テストでは、この屋根頂部に限る高さ上限を「固定した旧最大値＋6.1 mm」とし、一般的な境界の緩和は認めません。

軒先の瓦は実際に薄い断面を持ちます。完全な形で露出する56個の瓦口について、旧メッシュと追加メッシュを合わせた168本の検査線で70 mmの開いた奥行きを確認しています。隅棟に隠れる切断端は、この検査対象に含めていません。既存の中実の丸い棟材は残るため、棟自体が中空とは主張しません。

抽出した舞台のネイティブデータを比較すると、追加は1,257,759バイト、同じgzip設定による差分は274,880バイトです。これらは制作データの実測であり、Windowsの最終ビルド容量ではありません。約50 MBの目標に対する実ビルド確認は別途必要です。

角ばった5点断面（14,772三角形）とも同じカメラで比較し、軒先の山と受け面が丸く読める9点断面を採用。5点断面に比べ10,240三角形、gzip比較で106,024バイト増えます。中央の近接面の見え方を優先した追加です。

## 検証

`python Source/test_noh_roof_detail.py` は、固定したv2.10舞台の小さなデータを使い、ワールド全体の再生成や過去のソースモジュールを必要とせず実行できます。

- 12個の元の生成バッチと15個の元のネイティブバッチを厳密照合
- 床から2.757 m未満には追加頂点なし。既存の低い位置の形状はすべて保持
- 屋根追加処理は既存メタデータ・マテリアル定義・呼び出し元グループを保持（木材仕上げの別処理は下記）
- 渡された乱数生成器、Pythonの乱数、NumPyの乱数の状態を保持
- 再生成は決定的。同じ追加処理の二重実行を拒否
- 追加の全バッチで閉じたシェル、外向きの巻き順、非縮退三角形とUVを確認
- 最終標高への+100 m変換後のfloat32データでも同じ検査を実施
- 旧屋根の不透明な4面に対して、瓦と棟が交差しないことを面内サンプルでも検査
- 木栓16本は元の持ち送りに埋もれず、既存の梁面に接続する位置にあることを検査

造形比較では、元のネイティブ舞台と追加形状を抽出したスタジオ照明のBlender比較を使用しました。今回のリリース画像は、統合後の実際のワールド全体を共有の夕景設定で描画しています。Unity／VRChatの実機画面、実ビルド容量、最終の写実的な仕上がりは未検証です。

## 屋外の木材仕上げ

統合した夕景の比較で、元のStageCypressがカウンター用の滑らかなARMを共有し、床が鏡のように光っていることを確認しました。Gチャンネルの中央値65/255と乗算値0.82から、入力上の代表的な粗さは約0.209でした。

この材質だけ、既存のwood_planks_greyのアルベド・法線・ARM・高さの4マップへ一括で切り替えました。新規画像は0。色、UV密度、粗さ倍率、形状、他97材質は維持しています。新しいARMの中央値215/255に対する代表値は約0.691です。これは入力値の比較であり、Unityの表示や実測反射を保証するものではありません。スキャンの木種をヒノキと同定した主張でもありません。

`stage_wood_finish.py` は明示的な4項目だけを変更し、元の設定の改変や二重実行を拒否します。6項目の追加テストで、他の形状・材質・乱数・feature条件・現行マニフェストを検査します。制作プレビューでは、同じカメラ・光・露出で鏡状の反射が落ち着き、木目と接合部が読めることを確認しました。GLBは高さマップのパララックスを再現せず、Unity側の4マップの見え方は未実行です。
