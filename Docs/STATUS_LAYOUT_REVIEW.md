The static Blender controls proofs render actual button geometry and Japanese atlas labels, not Unity TextMesh. Their provenance retains the installer hash actually used for those frames. Later installer changes affect dynamic status ink, character size, and audit code only; button positions, shapes and UVs remain unchanged.

Dynamic status uses the blank upper panel area. The audit compares the bounds width of I and twenty M characters, fails if no meaningful refresh is observed, checks representative two-line clock and BGM error bounds, and restores original text in finally. This has only source tests here. It is not evidence that Unity refreshes bounds synchronously or that actual runtime text fits; execute menu 8b and inspect in Unity/VR.

The documentation-source comparison JSON is a historical source inspection, not a digest admission of later installer revisions. Package file hashes and current test logs identify the final candidate.
